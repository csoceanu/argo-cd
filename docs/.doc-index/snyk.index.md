# SNYK Documentation Index

## Overview
This documentation area provides a centralized dashboard for security vulnerability reports generated by Snyk for the Argo CD project. It tracks and summarizes security scan results for the `master` branch and the three most recent minor releases, covering application dependencies, container images, and Infrastructure-as-Code (IaC) manifests.

## Files Summary
*   **snyk/index.md**: Acts as the primary landing page and summary dashboard, displaying vulnerability counts (Critical, High, Medium, Low) for Go dependencies, UI dependencies, container images, and installation manifests across different Argo CD versions.

## Code Changes That Would Require Documentation Updates
*   **Release Lifecycle Events**: When a new minor release is cut or a patch is issued, the version tables in this file must be updated to reflect the "three most recent minor releases" policy.
*   **Base Image Version Updates**: Any change to the versions of third-party container images used by Argo CD (e.g., updating `redis:7.2.7-alpine` to a newer version or changing `dex` or `haproxy` versions).
*   **Dependency Management Changes**: If the project introduces new package managers or changes the location of existing ones (e.g., moving the UI directory or changing from Yarn to another tool).
*   **New Infrastructure Components**: Adding new sidecars or core components that require container image scanning (e.g., adding a new metrics exporter or specialized controller).
*   **Manifest Changes**: Renaming, adding, or removing core installation manifests (like `install.yaml` or `namespace-install.yaml`) that are tracked for IaC (Infrastructure as Code) vulnerabilities.
*   **Registry Migration**: Changing the container registry used for project images (e.g., moving from `quay.io` to `ghcr.io` or AWS ECR).
*   **Scan Policy Changes**: Changing the frequency of scans (currently Sunday) or the specific branches targeted for security analysis.

## Key Technical Concepts
*   **Snyk**: The third-party security platform used to perform Static Analysis Security Testing (SAST) and Software Composition Analysis (SCA).
*   **Vulnerability Severity**: Classification of security risks into Critical, High, Medium, and Low tiers.
*   **go.mod**: The Go modules file used for scanning backend library vulnerabilities.
*   **ui/yarn.lock**: The lockfile used for scanning frontend/UI JavaScript dependency vulnerabilities.
*   **Container Image Scanning**: Analysis of specific image tags (e.g., `quay.io/argoproj/argocd`, `ghcr.io/dexidp/dex`) for OS-level and application vulnerabilities.
*   **IaC (Infrastructure as Code) Scanning**: Security analysis of Kubernetes manifests (`install.yaml`) to detect misconfigurations.
*   **Master vs. Release Branches**: The distinction between the bleeding-edge development branch and stable, supported versions of the software.

## Related Components
*   **Argo CD Server/Controller**: The primary application scanned via `go.mod`.
*   **Argo CD UI**: The frontend component scanned via `yarn.lock`.
*   **Redis**: The state/cache component included in the container scan reports.
*   **Dex**: The identity service component included in the container scan reports.
*   **HAProxy**: The load balancing component included in the container scan reports.
*   **CI/CD Pipeline**: The automated system that triggers these Snyk scans every Sunday.
*   **Argo CD Installation Manifests**: The YAML files used for deploying the system, which are monitored for IaC security best practices.
