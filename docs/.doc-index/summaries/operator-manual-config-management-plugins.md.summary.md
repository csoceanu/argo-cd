This documentation provides a technical guide for extending Argo CD’s manifest generation capabilities using **Config Management Plugins (CMPs)**. It specifically focuses on the modern **sidecar-based architecture** which replaced the deprecated ConfigMap-based plugin system.

### 1. Primary Purpose
The file documents how to create, install, and manage custom plugins that allow Argo CD to support non-native configuration management tools (beyond Helm, Kustomize, and Jsonnet). It explains the lifecycle of manifest generation when delegated to a sidecar container running alongside the `argocd-repo-server`.

### 2. Key Topics Covered
*   **Plugin Configuration**: Detailed breakdown of the `ConfigManagementPlugin` manifest structure (init, generate, discovery, and parameters).
*   **Installation & Registration**: How to patch the `argocd-repo-server` to include a plugin as a sidecar.
*   **Plugin Discovery**: Logic for automatically matching a plugin to a repository based on file patterns or discovery commands.
*   **Data Passing**: Methods for passing environment variables and UI-driven parameters from the `Application` spec to the plugin.
*   **Security & Permissions**: Guidelines on running as non-root (UID 999), handling Git credentials, and preserving file modes.
*   **Performance Optimization**: Techniques like tar exclusions and manifest-generate-paths to speed up processing in monorepos.
*   **Migration**: Steps to transition from the deprecated `argocd-cm` configuration to the sidecar model.

### 3. Technical Keywords
*   **Components**: `argocd-repo-server`, `argocd-cmp-server` (the entrypoint/gRPC service).
*   **Manifest Fields**: `ConfigManagementPlugin`, `init`, `generate`, `discover`, `parameters`, `static`, `dynamic`, `preserveFileMode`, `provideGitCreds`.
*   **Environment Variables**: `ARGOCD_ENV_*` (user-defined), `ARGOCD_APP_PARAMETERS`, `KUBE_VERSION`, `KUBE_API_VERSIONS`, `ARGOCD_EXEC_TIMEOUT`, `ARGOCD_ASK_PASS_SOCK`.
*   **Configuration Files**: `plugin.yaml` (located at `/home/argocd/cmp-server/config/`).
*   **Optimization/Control**: `argocd.argoproj.io/manifest-generate-paths`, `plugin-tar-exclude`, `reposerver.plugin.tar.exclusions`.

### 4. Target Audience
*   **Argo CD Administrators/Operators**: Responsible for configuring the Argo CD infrastructure and installing third-party tools.
*   **Platform Engineers**: Who build internal tooling and need to integrate custom templating engines (e.g., Tanka, Pulumi, or custom shell scripts) into the GitOps pipeline.

### 5. Related Concepts
*   **Native Tools**: Helm, Kustomize, and Jsonnet (the tools CMPs are intended to supplement or replace).
*   **Argo CD Application Controller**: The component that consumes the manifests generated by the repo-server/CMP.
*   **Kubernetes Sidecars**: The architectural pattern used to isolate the plugin environment from the core Argo CD components.
*   **GitOps Workflow**: The overall process of syncing desired state from Git to Kubernetes.
