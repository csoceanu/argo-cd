# USER-GUIDE/COMMANDS Documentation Index

## Overview
This documentation provides a comprehensive reference for the Argo CD Command Line Interface (CLI), covering the lifecycle management of applications, projects, clusters, and repository credentials. It serves as the primary resource for both standard user operations and advanced administrative tasks—including RBAC validation, notification troubleshooting, and system configuration—while acting as the source for autogenerated help text and manual reference.

## Code Changes That Would Require Documentation Updates

*   **CLI Infrastructure**: Renaming commands, adding new `cobra.Command` subcommands, or modifying global "inherited options" (e.g., new auth flags like `--oidc-token`).
*   **Flag Modification**: Adding, removing, or changing default values for flags (e.g., timeout variants, output formats, or Kustomize parameters).
*   **Core Logic & Sync Engine**: Changes to sharding algorithms, the "Diff" engine (e.g., `ignoreDifferences` handling), or sync policy logic (automated pruning, retry backoff).
*   **API & Data Structures**: Changes to Protobuf definitions or Go structs (like `ApplicationSpec`) that alter data returned by `get` or `list` commands.
*   **Security & RBAC**: Updates to the Casbin-based RBAC engine, new resource types, or changes to how GPG keys are validated.
*   **Plugin & Manifest Support**: Adding support for new manifest generation tools, OCI providers, or updated versions of Helm/Kustomize.
*   **Notifications Engine**: New notification triggers, recipient types (integrations), or changes to the template rendering engine.
*   **Connectivity & Scoping**: Changes to how Argo CD handles multi-namespace installations, application sharding, or SSO login flows.

## Key Technical Concepts

*   **AppProject (proj)**: Logical isolation boundary defining allowed sources, destinations, and resource types.
*   **ApplicationSet (appset)**: Automation tool for generating multiple applications from a single template.
*   **RBAC Policy**: Casbin-based CSV rules defining "Who can do What on Which resource."
*   **Sync Strategy & Windows**: Mechanisms (`apply` vs `hook`) and cron-based schedules that control when synchronization occurs.
*   **Resource Overrides**: Lua-based customizations for health checks, custom actions, and diffing behavior.
*   **Sharding**: Horizontal scaling mechanism to distribute resource monitoring across controller shards.
*   **Manifest Generation**: Transforming Helm, Kustomize, or Jsonnet templates into raw Kubernetes YAML.
*   **Multi-Source Support**: Ability for an application to pull manifests/values from multiple repositories.
*   **Namespaced Mode**: A model where Argo CD is restricted to managing specific namespaces rather than the entire cluster.
*   **Orphaned Resources**: Live cluster resources not defined in the application's Git source.
*   **JWT Tokens**: Tokens used for programmatic API access via accounts or project roles.
*   **CLI Contexts & Impersonation**: Switching between servers and performing actions on behalf of other users/groups.

## Related Components

*   **Argo CD API Server**: The primary gateway for CLI requests and state management.
*   **Application Controller**: The engine that monitors state, calculates diffs, and performs synchronization.
*   **Repo Server**: Manages repository connections and manifest generation (Helm/Kustomize/Plugins).
*   **Notifications Controller**: Processes triggers and sends alerts based on templates.
*   **ApplicationSet Controller**: Orchestrates the lifecycle of applications generated by ApplicationSets.
*   **Redis**: Used for caching repository status and application state; sensitive to compression/password settings.
*   **Argo CD ConfigMap (argocd-cm) & Secrets**: Global sources of truth for administrative settings.
*   **Dex/OIDC**: Integrated identity providers impacting login and authentication flows.
*   **Kubernetes API Server**: The ultimate target for resource management and `--core` mode administrative actions.
