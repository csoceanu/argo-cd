# PROPOSALS/MANIFEST-HYDRATOR Documentation Index

## Overview
This documentation describes the Manifest Hydrator proposal for Argo CD, a feature designed to transform Helm charts or Kustomize templates into plain Kubernetes manifests and push them back to a Git repository. Its primary purpose is to provide a fully auditable and transparent history of an application's state by persisting the rendered "hydrated" output in version control.

## Files Summary
*   **proposals/manifest-hydrator/README.md**: Provides the conceptual framework for manifest hydration, instructions for configuring Git push credentials using a dedicated namespace and secret type, and references the transition from standard source fields to the `sourceHydrator` field.

*   **Migration Tooling**: Introduction of automated scripts or CLI commands to migrate existing Applications from `source` to `sourceHydrator`.

## Key Technical Concepts
*   **Manifest Hydration**: The process of rendering high-level templates (Helm/Kustomize) into static, "hydrated" Kubernetes YAML.
*   **sourceHydrator**: The specific Application field used to configure the hydration and push behavior.
*   **repository-push**: A specialized secret type (`argocd.argoproj.io/secret-type`) used exclusively for Git write access.
*   **argocd-push Namespace**: The designated secure namespace for storing Git push credentials, separate from standard pull secrets.
*   **State Transparency**: The design goal of ensuring that the live cluster state exactly matches a discoverable version in Git.
*   **Hydrated Manifests**: The resulting plain Kubernetes objects generated by the transformation process.

## Related Components
*   **Argo CD Application Controller**: Responsible for reconciling the state and triggering the hydration process.
*   **Argo CD Repo Server**: The component that performs the actual rendering/generation of manifests.
*   **Argo CD API Server**: Handles the management of the secrets and Application CRDs.
*   **Git/SCM Providers**: External systems (GitHub, GitLab, Bitbucket) that receive the pushed hydrated manifests.
