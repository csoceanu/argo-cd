# Documentation Style Guidelines

## Voice and Tone
- Use **active voice** throughout all documentation
- Maintain a professional but approachable tone
- Address the reader directly as "you" (second person)
- Use present tense for descriptions ("The controller syncs..." not "The controller will sync...")

## Structure
- Use sentence case for all headings (capitalize only the first word and proper nouns)
- Keep paragraphs to 3-4 sentences maximum
- Use numbered lists for sequential steps, dashes for unordered items
- Start each list item with a capital letter

## Technical Writing
- Define acronyms on first use: "Custom Resource Definition (CRD)"
- Use backticks for inline code, CLI commands, file paths, and configuration keys
- Use code blocks with language annotation for multi-line examples
- Prefer concrete examples over abstract descriptions
- Include the expected output when showing CLI commands

## Formatting
- Use **bold** for UI elements and important terms on first mention
- Use `monospace` for code, commands, paths, and config values
- Do not use italic for emphasis — use bold instead
- Keep line length under 120 characters where practical
